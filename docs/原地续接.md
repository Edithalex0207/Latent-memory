# 原地续接

上下文快满的时候，常见的办法有两种：开新窗口，前面的细节得自己再讲一遍；或者 `/compact` 压缩，多跑一次摘要，原话和思考变成几段概括。

原地续接是第三种：把旧会话最近一段对话**原样**留下（连 thinking 一起），前面的裁掉，换一个新的会话 id 接着跑。不跑摘要，也不加“前情提要”，模型读到的是一段完整的、自己的对话。界面上还是同一个窗口。

被裁掉的那部分不会丢：裁之前先按[《后台落档》](后台落档.md)把还没整理的对话收进记忆库，再往 Latent 写一个续接检查点。之后聊到那些事，靠检索和自动浮现想起来。

随包的参考实现是 `src/forge_session.py`，只用 Python 标准库，处理的是 Claude Code 的会话记录。

## 谁能用

| 你的前端 | 怎么用 |
|---|---|
| 驱动 Claude Code 命令行的自建前端：常驻一个 `claude -p --input-format stream-json` 进程，或者每轮起一次 `claude -p --resume <id>` | 直接用 `forge_session.py`，见下文 |
| 直接调模型 API、自己管消息数组的前端 | 不需要这个脚本，照下面“做法”那几条在自己的消息数组上做：留尾部原话、从人说的话切、先落档和存检查点再裁 |
| Claude Code 终端或桌面端，人自己在用 | 进程换不了，只能手动：退出后跑一次 `forge`，再用 `claude --resume <新id>` 打开 |

## 做法

1. **到门槛才动**：读会话里最近一轮的真实用量（`input_tokens + cache_creation_input_tokens + cache_read_input_tokens`），超过 `--threshold` 才续接。
2. **先保住要裁的部分**：
   - 加 `--archive` 时，先把落档游标之后没整理的对话整理进记忆库（不看门槛）。没跑完就不裁。
   - 配了 `LATENT_MCP_URL` 时，再用 `latent_thread_close` 写一个检查点，记下最近的话头。写不进去就不裁。
3. **切点**：从尾部往前累加到刚超过 `--retain` 的位置，再往后找第一条人说的话，从那里切。纯工具结果、meta 消息不算人说的话，免得从半截工具回合接起。
4. **原样保留**：保留区间里的 user/assistant 事件原样写进新文件，thinking 不去掉。去掉 thinking 之后，模型会从历史里学到“这里不思考”，之后很多轮都压着不想。
5. **工具先例**：保留区间里没有一次完整的工具调用时，从更早的地方捞最近 1～2 次成功调用垫在最前面（去掉 thinking，工具结果压成 200 字以内）。否则模型看不到自己用过工具，会说自己不能用，或者假装调用。
6. **重建父链**：新会话 id，第一条 `parentUuid` 为空，之后每条指向前一条。只改 `sessionId` 不重建父链的话，恢复时会沿父链撞到指向旧会话的 uuid，整段被当成断链丢掉。
7. **写到同目录**：新文件写在旧会话文件旁边（`~/.claude/projects/<项目>/<新id>.jsonl`），旧文件不删。

## 接进自建前端

1. 每轮结束后跑一次 `check`，或者自己从 stream-json 输出里读最近那条 assistant 消息的 `usage`：

   ```bash
   python3 src/forge_session.py check ~/.claude/projects/<项目>/<会话id>.jsonl
   ```

   输出 `{"contextTokens": …, "threshold": …, "shouldForge": true/false}`。

2. 到门槛时，在两轮之间（模型没在回复）跑：

   ```bash
   export LATENT_MCP_URL=http://127.0.0.1:8765/mcp LATENT_MCP_TOKEN=<普通token>
   export LATENT_ARCHIVE_ME=<AI 的名字> LATENT_ARCHIVE_USER=<你的名字>
   python3 src/forge_session.py forge ~/.claude/projects/<项目>/<会话id>.jsonl --archive
   ```

   输出 `forged` 时带新的 `sessionId`；`skip` 是不用裁；`aborted` 是落档或检查点没成功，没裁，原会话照常用，下一轮再试。

3. 换到新会话：
   - 每轮起一次进程的：下一轮把 `--resume` 换成新 id。
   - 常驻进程的：起一个 `claude -p --input-format stream-json --output-format stream-json --resume <新id>` 的新进程，等它输出 `system`／`init` 事件，确认起来了再把下一条消息交给它，然后关掉旧进程。新进程没起来就继续用旧的，不要先关旧的。

## 参数

| 参数 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `--threshold` | `LATENT_FORGE_THRESHOLD` | 700000 | 最近一轮真实上下文超过多少才续接 |
| `--retain` | `LATENT_FORGE_RETAIN` | 300000 | 续接后留下多少；必须小于门槛 |
| `--archive` | | 关 | 裁之前先落档（读 `LATENT_ARCHIVE_*`，见《后台落档》） |
| `--url`／`--token` | `LATENT_MCP_URL`／`LATENT_MCP_TOKEN` | 无 | 配了就写检查点 |
| `--window` | | 第几次续接 | 检查点的窗口号 |
| `--force` | | 关 | 不看门槛，只要超过保留量就裁 |
| `--state-dir` | `LATENT_FORGE_STATE_DIR` | `~/.cache/latent-forge` | 记续接次数 |

默认的 700000／300000 是按 100 万上下文的模型定的：留 30 万余量，一轮里的大工具输出、图片顶不到上限。上下文小的模型要按比例调低，**门槛要低于 Claude Code 自己自动压缩的位置**，否则它先压缩了，续接永远轮不到。

## 验过什么

- `--selftest`：合成会话，覆盖真实用量与切点、干净边界、工具先例、父链与 uuid、thinking 保留、不到门槛不写、检查点或落档失败不裁，并用真服务端写检查点。
- 真 Claude Code 恢复：在 Claude Code 2.1.303 上建了一个三轮的真会话，每轮记一个暗号，用 `forge` 只留最后一轮，再 `claude -p --resume <新id>` 问记得哪几个。模型答出了留下的那个，前两个说看不到，没有报错。只跑了一次，会话很短，也没有带工具调用和 thinking。

## 已知限制

- 只认 Claude Code 的会话记录格式。别的命令行客户端的会话文件结构不同，要照着“做法”自己写。
- 模型回复途中人插进来的话，Claude Code 记成 `attachment`，不是 user 事件，续接时不带进新会话（落档会收）。
- 自动浮现的参考 hook 按会话 id 记账：换了新 id，同一会话的注入预算和“已注入过”的记录会从零开始，保留区间里已经出现过的旧资料可能被再注入一次。
- 每次续接会让模型提供方的提示缓存整段重写一次，所以门槛不要设得太低、太频繁。
